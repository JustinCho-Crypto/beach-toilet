# UI 패턴 레퍼런스 — 검증된 화면 구성

geumsongaji(한우 키우기, **정식 출시 완료**)에서 실제로 쓰인 패턴을 코드에서 뽑은 것. **M1/M2에서 화면을 새로 설계하기 전에 먼저 이 문서를 보고, 맞는 패턴이 있으면 그대로 재사용하거나 spec에 맞게 변형할 것.** 당근마켓 "당근농장"류 UI를 의도적으로 참고한 결과물이며, 실기기·실광고·실유저 환경에서 검증된 내용이다.

## 색상 / 배경

- 전체 배경: 세로 그라데이션 흰색→베이지/골드. `LinearGradient degree={180} colors={['#FFFFFF', '#FFFDF4', '#FFF1D6']} positions={[0, 0.4, 1]}`를 `StyleSheet.absoluteFill`로 화면 맨 위에 깔고 그 위에 콘텐츠를 얹는다.
- 화면 바탕색(`screen.backgroundColor`)은 순수 흰색이 아니라 `#FFFDF6` (아주 옅은 크림톤).
- 카드·pill은 항상 `colors.white` 배경 — 그라데이션 배경 위에서 붕 떠 보이게.
- 보상/강조는 `colors.orange400~700` 계열(성장률, 마블링 게이지). 양수 피드백(획득 가능, 리필 타이머)은 `colors.green` 계열. 금액·핵심 수치는 `colors.grey900`(진하게), 보조 캡션은 `colors.grey500~600`(옅게).
- "지금 할 수 있는 행동" 표시는 `Badge size="tiny|small" type="green" badgeStyle="weak"` 조합 — 얇고 옅은 뱃지 하나로 충분, 화려한 강조 금지.

## 첫 실행 온보딩 (팝업 금지, 풀스크린 스텝 페이지)

핵심 재화를 "뭘 하면 버는지"는 화면만 보고 알 수 없다 — 신규 유저에게 반드시 온보딩으로 알려준다. **바텀시트 팝업이 아니라 풀스크린 스텝 페이지로 만들 것.** 40~60대는 팝업을 읽지 않고 닫는 비율이 높고, 페이지는 실제 게임 에셋으로 보여주면서 가르칠 수 있다. (geumsongaji `src/components/Onboarding.tsx`)

구조:
- **스텝 배열 데이터 주도**: `STEPS: {비주얼, title, sub, cta}[]` 배열 하나로 정의하고 렌더는 공용. 3~4스텝, 스텝당 메시지 1개.
- 스텝 구성 공식: ① 코어 액션(뭘 누르면 뭐가 되는지) → ② **재화 획득 경로**(제일 중요 — 이걸 위해 온보딩이 존재한다) → ③ 최종 목표/환금(토스포인트 교환까지 연결) → ④ "자, 시작해보세요!" + **시작 선물 + 게임 진입 CTA**.
- 마지막 CTA는 게임 내 기존 버튼과 동일한 문구/스타일로(예: "새 송아지 받기") — 튜토리얼 완료가 곧 첫 플레이 개시가 되게 한다.
- 시작 선물은 진입 직후 플로팅 이펙트("여물 +10")로 한 번 더 보여준다. 지급량 문구와 실제 지급량은 반드시 일치시킬 것(기본 지급 위에 +N이면 "N개를 **더** 드릴게요").
- 비주얼: 상단 진행 도트(8px 원, 활성 `colors.blue500`/비활성 `grey200`) + 중앙 캐릭터(단계별로 작은→큰 에셋 교체) + 반복 이펙트(획득 스텝엔 재화가 계속 떠오르는 `Animated.loop`) + 스텝 전환 페이드인(280ms). 하단은 `FixedBottomCTAWithoutConsumer` 고정.
- 상태 관리: `GameState.onboarded?: boolean`. **기존 저장 데이터가 있으면 마이그레이션에서 `?? true`** (업데이트로 온보딩이 추가돼도 기존 유저에겐 안 뜬다), 저장이 전혀 없을 때만 `false`. 홈 컴포넌트에서 `if (!state.onboarded) return <Onboarding onDone={completeOnboarding}/>`.
- **온보딩 실기기 테스트**: 미니앱은 삭제/재설치 개념이 없어 공식 Storage를 못 지운다. 저장 키만 바꾼 테스트 전용 빌드(`STORAGE_KEY = 'xxx/onboarding-test-N'`)를 뽑아 QR로 확인하고, **배포는 반드시 원래 키의 빌드로** 할 것 (테스트 키 빌드를 배포하면 전 유저 데이터가 초기화된 것처럼 보인다).

## 홈 첫 진입 코치마크 (온보딩 직후)

온보딩 페이지를 넘긴 유저도 홈에서 "뭘 눌러야 하지?"로 멈춘다. 첫 코어 액션을 손가락으로 짚어준다.

- 무대(캔버스)만 살짝 어둡게(`rgba(25,31,40,0.22)` — 진하면 답답하다) + 대상 위/아래에 👆(`u1F446`) 이모지를 `Animated.loop`로 까딱까딱(±16px, 460ms).
- 손가락은 **대상과 겹치지 않게 아래에 배치**하고, 이모지 글리프의 손끝이 중앙에서 살짝 왼쪽이므로 x를 보정한다.
- 안내 문구는 대상 **위쪽에 작은 흰 캡슐**로 (검은 큰 블록은 위압적이다).
- **코치마크 해제 = 첫 코어 액션 수행**. 별도 닫기 버튼 없이 그 행동을 하면 사라지고, 상태 플래그(`coachDone`)로 재노출 방지. 기존 유저는 마이그레이션에서 `?? true`.
- 코치마크가 떠 있는 동안엔 기본 안내 말풍선을 숨기고, 평상시 말풍선은 **상황이 있을 때만**(로딩/게이트/완료/소진) 띄운다 — 항상 떠 있는 안내는 노이즈가 된다.

## 커스텀 공유 (멘트 + 링크 미리보기)

기본 공유는 "앱 설치 없이 바로 쓸 수 있어요" 같은 플랫폼 공통 티저가 나간다. 우리 문구·이미지로 바꾸려면:

- `getTossShareLink(경로, ogImageUrl)` + `share()` — **둘 다 `@apps-in-toss/native-modules`에서 import** (framework에는 노출 안 됨). OG 적용은 토스 앱 Android 5.240+/iOS 5.239+, 구버전은 링크만 동작.
- OG 이미지: **1200×600 webp**, 여백 없이 꽉 채운 풀블리드로. https 접근 가능한 정적 호스팅에 올린다(GitHub raw로 충분).
- **이미지를 교체할 땐 반드시 새 파일명으로 올릴 것** — 카카오는 URL 단위로 미리보기를 캐싱해서 같은 이름으로 덮으면 옛 이미지가 계속 보인다.
- 전송을 실제로 했는지 확인해야 하는 보상(검증형)은 `contactsViral`의 `sendViral` 이벤트만 신뢰할 수 있다. 커스텀 공유는 "시트를 열었다"까지만 알 수 있어서, **앱 복귀(AppState) + 5초 이상 체류**를 조건으로 걸어 즉시 취소 어뷰징을 막는다.
- 두 방식을 한 시트에 나란히 두는 게 표준: [카톡·메시지로 공유하기(fill)] + [토스 친구에게 추천하기(weak)].
- ⚠️ 카카오톡으로 공유된 메시지 끝에 빈 줄이 붙는 현상은 **카카오 공유 확장이 재조립하며 넣는 것**으로, 앱에서 제거 불가(복사 액션은 깨끗함). 시간 쓰지 말 것.

## 레이아웃 골격 (메인 화면)

1. **상단 헤더**: 진행률 게이지 + 상태 텍스트 1줄(굵게, 예: "몸무게 320kg") + 같은 줄에 보조 캡션(옅게, 예: "출하까지 430kg 남았어요").
2. **캔버스(무대)**: 고정 높이 사각 카드(`borderRadius: 24`, `overflow: hidden`). 배경 일러스트(플랫한 사각형/원 조합으로 충분, 정교한 그림 불필요) 위에 절대좌표로 배치:
   - 좌상단/우상단에 재화 표시 pill (흰 배경, `borderRadius: 999`, 아이콘+숫자)
   - 중앙에 탭 가능한 캐릭터/오브젝트 (`Pressable` + `Animated.View`)
   - 캐릭터 아래 말풍선(흰 pill, 현재 상태 안내 1줄)
   - 최하단에 보조 진행바(옅은 배경의 pill, 라벨+ProgressBar+수치)
3. **액션 카드 2개 가로 배치** (`flexDirection: row`, `gap: 10`): 좌측에 이모지(32×32) 크게, 우측에 캡션(옅은 색, 작은 글씨)+타이틀(굵게) 2줄. 이 포맷 하나로 급여/출석/공유 등 반복 액션 전부를 통일한다 — 화면마다 다른 카드 디자인을 만들지 말 것.
4. **광고 블록은 별도 흰 카드로 격리**하고 에러 바운더리로 감싼다 (아래 "광고 지면 UI" 참고).
5. **하단 전환 버튼**: `Button type="primary" display="block" size="big"`. 조건부 강조: 지금 갈 이유가 있으면 `style="fill"`, 아니면 `style="weak"` (예: 출하 가능 여부).
6. 같은 줄에 놓이는 pill들은 **패딩을 동일하게** (`paddingHorizontal: 12, paddingVertical: 7`) — 내용 길이가 달라도 높이가 맞아야 한다.

## 광고 지면 UI (배너 + 리워드) — 전부 실전 크래시/장애에서 나온 규칙

**배너(InlineAd):**
- **`InlineAd`를 쓰는 화면의 스크롤 컨테이너는 반드시 `@granite-js/react-native`의 `IOScrollView`** (일반 `ScrollView` 금지). InlineAd 내부의 ImpressionArea가 IOContext.Provider를 요구해서, 일반 ScrollView 안에서는 **앱 전체가 "잠시 문제가 생겼어요"로 죽는다**. 검수 통과 후 실배포에서 터진 버그.
- InlineAd는 3중 방어로 감싼다 (홈이 광고 때문에 죽으면 안 된다):
  1. **지연 마운트**: 첫 렌더 후 `setTimeout(..., 1000)`으로 마운트 — 초기 구동과 광고 SDK 초기화를 분리.
  2. **에러 바운더리**(클래스 컴포넌트 `getDerivedStateFromError`): 크래시 시 그 블록만 placeholder("광고 영역 · AD")로 전환.
  3. **`onNoFill` / `onAdFailedToRender` 콜백**에서 placeholder로 전환 — no-fill은 정상 상황이므로 에러 표시 금지.
- placeholder에 `onLongPress` 진단을 심어두면(마지막 실패 사유를 Alert로) 실기기에서 원인 파악이 빨라진다. 일반 유저는 발견 못 하는 수준이라 프로덕션에 남겨도 된다.
- 콘솔 지면 유형은 "이미지 강조 배너" + `variant="card"` 조합 사용.

**리워드 광고 흐름 UI:**
- 광고 호출 중 상태는 **팝업이 아니라 화면 내 상시 요소의 상태 변화**로 보여준다: 캐릭터 말풍선을 "광고 불러오는 중" + `ActivityIndicator`로 전환. 로딩 팝업을 띄웠다 닫으면 촌스럽고, 연타로 팝업이 쌓인다.
- **중복 호출 가드는 `useRef(false)`로** (state만으로는 연타 레이스에 뚫린다). 시작 시 `ref.current = true`, 모든 종료 경로(onReward/onDismissWithoutReward/onUnavailable)에서 해제.
- 보상 지급·이펙트는 **광고가 dismissed 된 뒤에** 실행한다. userEarnedReward 시점에 실행하면 광고가 화면을 덮고 있어 이펙트가 안 보인다.
- 실패 시에만 Alert 폴백: "광고를 불러오지 못했어요. 잠시 후 다시 시도해주세요." + 사유를 괄호로. **프로덕션에서 mock 보상 지급 절대 금지** (치팅 통로가 된다) — mock은 샌드박스 분기에서만.
- 광고로 잠긴 액션의 버튼/카드 문구는 예외 없이 "광고 보고 ○○하기" 형식으로 행동 맥락과 대가를 함께 표기한다 ("광고 보기" 단독 금지). 문구를 깔끔하게 만들려고 "광고 보고"를 뺐다가 유저가 광고를 예상 못 하는 문제로 되돌린 이력 있음 — 일관 표기가 정답. 일일 캡 도달 시엔 "내일 또 받을 수 있어요"류의 다음 행동 안내로.

## 화면 간 이펙트 전달 (pendingEffects)

서브 화면(경매 등)에서 확정된 보상을 홈에서 연출해야 할 때: 모듈 스코프 싱글톤(`pendingEffects.salePayout = N`)에 예약해두고 `navigation.goBack()`, 홈에서 `navigation.addListener('focus', ...)`로 감지해 재생 후 0으로 리셋. 완료 팝업 없이 "돌아오니 돈이 날아든다"가 팝업+확인버튼보다 훨씬 낫다.

## TDS 함정 워크어라운드 (검증된 버그)

- **`Badge`를 절대배치/Animated 컨테이너 안에서 쓰면 텍스트가 중앙에서 어긋난다** → 커스텀 pill로 대체: `View`(`borderRadius: 999`, `paddingHorizontal: 14, paddingVertical: 6`, 시맨틱 배경색) + `Txt`. 일반 플로우 레이아웃에서는 Badge 그대로 써도 된다.
- **`FixedBottomCTAWithoutConsumer`는 그라데이션 배경 위에서 `gradient={null}` 필수** — 기본값이 흰 그라데이션 띠를 깔아서 배경이 끊겨 보인다.
- `topAccessory`에 넣는 보조 버튼은 `<View style={{flex: 1}}>`로 감싸야 전체 폭이 된다. 추가 마진 금지(TDS가 이미 16을 준다).
- `LinearGradient`에 색 3개 이상 쓰려면 `easing="linear"` 명시 필요.

## 인터랙션 ("만지는 맛")

- 캐릭터 탭 → `Animated.sequence`로 짧게 확대(1.06~1.14배, 90~200ms)→원복. 손맛은 이 스케일 펄스 하나로 충분하다.
- **보상/피드백은 텍스트를 고정 노출하지 않고, 떠올랐다 사라지는 플로팅 아이템으로 표현한다** (하트 ♥, `+Nkg`, 동전 등). 화면에 박제된 숫자보다 이 방식이 반복 조작의 손맛을 훨씬 크게 만든다.
  - 일반 텍스트류: `Easing.out(quad)`, ~900ms, 위로 떠오르며 페이드아웃
  - 목표 지점(지갑 등)으로 흡수되는 연출(동전 등): `Easing.in(quad)`, ~700ms, 시작 좌표→목표 좌표로 translateX/Y 보간
  - 등장 스케일: `[0, 0.2, 1]` 구간에서 `[0.5, 1.15, 1]`로 — 살짝 튀어나오듯 팝업 후 안착
- **랜덤 결과(가챠/경매류)는 "감속하는 룰렛" 패턴**: 처음엔 짧은 간격(~70ms)으로 후보를 빠르게 순환 표시하다가 점점 간격을 늘리며(110→170→260→380ms) 감속, 정지 시 화면 흰색 플래시(opacity 0→0.85→0, ~300ms) + 결과 도장 연출(`Animated.spring`, `friction: 5, tension: 120`, scale 2.6→1)로 확정감을 준다.
- **숫자 카운트업**: 목표값까지 ~24스텝으로 나눠 35ms 간격으로 증가시키고, 매 스텝마다 살짝 펄스(scale 1.08→1, 30~40ms)를 곁들인다. 그냥 값이 툭 바뀌지 않게.
- **대기/긴장 상태 표현**: 좌우로 짧게 흔드는 반복 애니메이션 (`rotate` interpolate ±3deg, 70ms 3단 시퀀스 loop).

## TDS 컴포넌트 사용 규칙

- 바텀시트는 항상 `BottomSheet.Root` + `Header` + `HeaderDescription` + `CTA` 표준 조합만 사용한다. 커스텀 모달을 새로 만들지 말 것.
- 서브 화면으로 이동한 뒤 하단 고정 액션은 `FixedBottomCTAWithoutConsumer` — `topAccessory`로 보조 버튼(예: "광고 보고 올리기")을 메인 CTA 위에 얹을 수 있다.
- 서브 화면 상단 타이틀 영역은 `Top`(`upper`=이모지 아이콘, `title`, `subtitle2`) 표준 패턴을 쓴다.
- 진행률 표시는 상황에 따라 둘로 구분: 캡슐 안에 텍스트를 함께 보여줘야 하면 커스텀 `LabeledGauge`(두꺼운 캡슐 트랙 + 중앙 텍스트), 단순 바면 TDS `ProgressBar`.

## 에셋 규칙

- 아이콘/이모지는 로컬 파일을 새로 만들지 말고 **토스 공식 3D 이모지 CDN**을 쓴다: `https://static.toss.im/3d-emojis/u{유니코드}.png` (예: `u1F42E.png` = 🐮). 실제 토스 앱들과 그래픽 톤이 통일되고 무료다. `src/game/emoji.ts`에 이름별 상수로 모아서 관리한다.
- 캐릭터/성장 단계처럼 **즉시 로딩이 보장돼야 하는 핵심 비주얼**은 PNG 파일 대신 base64 data URI로 코드에 내장한다(예: `imageData.ts`). 네트워크 이미지의 로딩 깜빡임을 없앤다. 대신 파일 용량이 커지므로(단계당 수백KB) 앱 하나에 2~4단계 정도로 제한할 것.

## 보상 알림 — 이중 팝업 금지

- 토스포인트 실지급 시 **토스가 자체 알림을 띄운다.** 앱에서 성공 팝업을 또 띄우면 이중 알림이 된다. 성공은 조용히(또는 인앱 이펙트만), **실패했을 때만** 안내한다.
- 실패 시 차감했던 재화는 자동 환불하고 "N냥은 그대로 돌려놨어요"처럼 복구 사실을 알린다.

## 문구 톤

- 실패/대기 상태 문구도 부정적으로 끝내지 않고 다음 행동을 안내한다. 예: "오늘 리필은 매진" 대신 "여물은 12분마다 1개씩 채워져요. 내일 또 리필할 수 있어요."
- 짧은 구어체, `~해요/~돼요` 종결. 느낌표 남발 금지.
- **재화 문구는 정확하게**: 직접 지급이 아닌 간접 이득을 "받아요"라고 쓰지 말 것 (예: 등급을 올리는 아이템은 "더 비싸게 팔 수 있어요"). 앱이 첫날부터 약속을 안 지키는 것처럼 보이면 신뢰가 깨진다. 지급량 표기도 실제 지급 로직과 1:1로 일치시킨다.
- 시간 카운트다운은 "N분 M초" 포맷 (1분 미만이면 "M초"). 초 단위 숫자만 덜렁 표시 금지.
- 게임 내 재화는 앱 세계관의 고유 명칭(예: "냥")으로 부르고, "원"·"포인트"는 토스포인트 전환 맥락에서만 쓴다.
